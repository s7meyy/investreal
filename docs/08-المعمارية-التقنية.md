# ٨) المعمارية التقنية

## ٨-١ المبدأ الحاكم

**المحرّك المالي حزمة TypeScript نقيّة، بلا أي اعتماد على الواجهة.**
دوال خالصة، مُدخَل واحد ومُخرَج واحد، مُغطّاة باختبارات.
هذا يسمح باستخدامه في الويب، وفي API، وفي تصدير Excel، وفي بوت واتساب لاحقاً،
ويجعل مراجعة صحّة الأرقام ممكنة بمعزل عن الشاشات.

## ٨-٢ الحزمة التقنية المقترحة

| الطبقة | الاختيار | السبب |
|---|---|---|
| الإطار | Next.js (App Router) + TypeScript | RTL و SSR وتصدير ثابت وسهولة النشر |
| التنسيق | Tailwind CSS بإعداد RTL | سرعة وانضباط بصري |
| الحالة | Zustand + نموذج مُتحقَّق بـ Zod | بسيط، والتحقّق يمنع مدخلات فاسدة |
| الرسوم | Recharts (مع ضبط RTL يدوي) | كافٍ ومقروء |
| التخزين | LocalStorage أولاً، ثم Supabase | ابدأ بلا حسابات؛ الحساب يأتي عند الحاجة للمزامنة |
| PDF | توليد من الخادم لضمان الخط العربي | تجنّب كوارث تشكيل الحروف في PDF من المتصفح |
| الاختبار | Vitest للمحرّك، Playwright لمسار كامل | المحرّك هو ما يجب أن يكون مضموناً |
| النشر | Vercel أو Netlify | سريع ومجاني للبداية |

## ٨-٣ هيكل المجلدات


## ٨-٤ نموذج البيانات (مختصر)

```ts
type Opportunity = {
  id: string; name: string; createdAt: string;
  property: { type: PropertyType; city: string; district: string;
              area?: number; ageYears?: number; units: Unit[] };
  deal: { termYears: number; contractRentAnnual: number;
          paymentSchedule: Payment[]; graceMonths: number;
          escalation?: number; renewalOption?: RenewalOption;
          calendar: 'gregorian' | 'hijri' };
  revenue: { marketRentAnnual: number; growthRate: number;
             occupancy: number; firstYearOccupancy: number;
             growthCap?: number; otherIncome: number };
  costs: { fitout: number; maintenance: Rate; management: Rate;
           marketing: Rate; insurance: number; utilities: number;
           fees: number; capexReserve: Rate; restoration: number };
  finance: { discountRate: number; inflation: number;
             vatApplies: boolean; zakatApplies: boolean; loan?: Loan };
  legal: LegalAnswers;        // يغذّي درجة المخاطرة
};

type Result = {
  cashflow: MonthlyRow[]; annual: AnnualRow[];
  metrics: Metrics;                 // IRR, NPV, MIRR, PI, payback, breakeven...
  scenarios: Record<'pessimistic'|'base'|'optimistic', Metrics>;
  sensitivity: TornadoItem[];
  monteCarlo?: { lossProbability: number; p10: number; p50: number; p90: number };
  risk: { score: number; band: RiskBand; items: ScoredRisk[] };

```

## ٨-٥ اعتبارات هندسية

- **العمليات المالية بأعداد صحيحة (هللات)** لتفادي أخطاء الفاصلة العائمة.
- **IRR بخوارزمية Brent** مع كشف تعدد الجذور والرجوع إلى MIRR.
- **مونت كارلو في Web Worker** حتى لا تتجمّد الواجهة.
- **إصدار للمحرّك (`engineVersion`)** يُحفظ مع كل فرصة، حتى تبقى النتائج
  المحفوظة قابلة للتفسير بعد تحديث المعادلات.
- **كل الحسابات على العميل في المرحلة ١** — خصوصية كاملة، لا بيانات تُرسل.
