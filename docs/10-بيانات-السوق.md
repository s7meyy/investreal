# ١٠) بيانات إيجارات السوق — سهيل وبسيطة

## ١٠-١ لماذا هذه أهم طبقة في المنصّة

تحليل الحساسية على الحالة المرجعية يُرتّب العوامل هكذا:

| العامل | تغيّر العائد عند ±٢٠٪ |
|---|---|
| **إيجار السوق** | **١٢٫٠ نقطة** |
| نسبة الإشغال | ٩٫٨ نقطة |
| الإيجار التعاقدي | ٩٫٦ نقطة |
| تكلفة التجهيز | ١٫٦ نقطة |
| نمو الإيجارات | ١٫٤ نقطة |
| الصيانة | ٠٫٧ نقطة |

**إيجار السوق هو المتغيّر الأقوى، وهو في الوقت نفسه المُدخَل الذي يقدّره
المستخدم بأضعف أساس** — غالباً من كلام المالك أو من أسعار إعلانات متفائلة.
ترك هذا الرقم لتخمين المستخدم يجعل كل دقّة المحرّك بلا معنى.

لذلك: **ربط المنصّة بمصدر إيجارات مرجعي ليس ميزة إضافية، بل هو ما يحوّل
الأداة من حاسبة إلى مرجع.**

## ١٠-٢ التصميم: طبقة مزوّدين لا تكامل مباشر

`packages/engine/src/marketData.ts` يُعرّف واجهة واحدة:

```ts
interface MarketDataProvider {
  id: string;
  label: string;
  fetchComparables(query: MarketQuery): Promise<MarketComparable[]>;
}
```

كل مصدر — سهيل، بسيطة، ملف CSV، إدخال يدوي — يُنفّذ هذه الواجهة.
`estimateMarketRent()` يجمعها ويُخرج تقديراً واحداً.

**ثلاثة قرارات تصميمية مقصودة:**

1. **الوسيط لا المتوسط.** التقدير يُبنى على الوسيط والمئينين ٢٥ و٧٥،
   لأن المتوسط تُفسده وحدة شاذة واحدة.
2. **التمييز بين العقد الموثّق وسعر الإعلان.** كل مقارنة تحمل `kind`،
   والتقدير يعرض نسبة العقود الموثّقة في العيّنة. الفرق بينهما في السوق
   السعودي كبير، وإخفاؤه تضليل.
3. **الفشل لا يُعطّل الأداة.** `Promise.allSettled` — مصدر لا يستجيب
   لا يُسقط البقية، والأداة تعمل كاملة بلا اتصال عبر `ManualProvider`.
   أداة تُستخدم على الجوال أثناء المعاينة يجب ألا تتوقف لأن API تأخّر.

### درجة الثقة
كل تقدير يحمل `confidence` تُحسب من: حجم العيّنة، ونسبة العقود الموثّقة،
وحداثة البيانات. تُعرض للمستخدم صراحةً — تقدير بثقة منخفضة يجب أن يبدو كذلك.

## ١٠-٣ حالة الموصّلين

`suhailProvider` و`baseetahProvider` مبنيان على `HttpProvider` الذي يحمل
شكل الطلب ودالة `parse` قابلة للحقن. **نقاط الوصول ومفاتيحها لم تُثبَّت بعد**،
لأن بيئة التطوير الحالية لا تصل إلى النطاقين، ولم أشأ اختراع عقود API
تبدو صحيحة وتفشل عند أول تشغيل حقيقي.

ما يلزم لإكمالهما — سؤال مفتوح لك:

- هل لديك حساب أو تعاقد مع «سهيل» أو «بسيطة»؟
- هل الوصول عبر واجهة برمجية رسمية، أم تصدير ملفات دورية،
  أم أن البيانات تُقرأ يدوياً من لوحاتهما؟

كل احتمال من الثلاثة مدعوم اليوم:

| الاحتمال | المكوّن الجاهز |
|---|---|
| واجهة برمجية | `HttpProvider` — يُضبط `baseUrl` و`apiKey` و`parse` |
| تصدير دوري CSV/JSON | `DatasetProvider` — يعمل بلا اتصال |
| قراءة يدوية | `ManualProvider` — المستثمر يُدخل ما رآه |

## ١٠-٤ كيف تُستخدم البيانات في الواجهة

1. المستخدم يُدخل المدينة والحي ونوع العقار.
2. المنصّة تعرض: «الوسيط في هذا الحي ٢٨٬٥٠٠ ريال (٢٥ عقداً موثّقاً،
   نطاق ٢٤٬٠٠٠–٣٣٬٠٠٠، ثقة عالية)» كقيمة افتراضية قابلة للتعديل.
3. لو أدخل المستخدم رقماً خارج النطاق ← تنبيه صريح لا منع:
   «تقديرك أعلى من المئين ٧٥ للحي — على ماذا تستند؟»
4. التقرير النهائي يذكر مصدر الرقم وتاريخه، فيعرف قارئ التقرير
   أيّ الأرقام مسنَد وأيّها تقدير شخصي.

**هذا وحده يعالج أخطر مخاطرة في المنصّة:** تقرير دقيق مبنيّ على مُدخَل خاطئ.
